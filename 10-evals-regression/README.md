# 10 · Regression suite for AI delivery work — Regression Pack

**For the owner:** a model update, a plugin edit or a settings change can quietly change what a client receives, with no error anywhere.
This pack runs the same frozen jobs before and after one change and prints a before/after report on quality, cost and time.
A person then writes keep, investigate or roll back on the decision line, before a client sees the change.

**Shown in:** Episode 10, "BUILD: nine frozen cases", "BUILD: the runner, the limits, the pin", "BUILD: the first baseline and the controlled change", "BREAK 2: the judge that marks its own work", "FIX: the real baseline", "FIX: the same test again, the decision, the rollout".

Kiran Studio, Mehr Bakery, Sufi Threads and Noor Dental Clinic are fictional. All data is synthetic. Costs in the result files are client-side estimates at list price (the recording ran on a subscription login), not invoices.

## Use it in 5 steps

1. **Check the prerequisites.** Python 3.11+, Claude Code installed and logged in (ideally an API key, for repeatable cost figures), and an eval machine: WSL or Linux with `bubblewrap` and `socat` for the sandboxed cases. The cases also call earlier episodes' assets: case 05 needs a venv at `~/ep10-venv` with the Agent SDK and Playwright Chromium (see `../04-website-qa-agent/requirements.txt`); case 06 needs the Episode 5 booking app (`../05-business-connector/noor-booking-app`, or set `NOOR_APP_SRC`) and the `kiran-noor` plugin admin-installed at `/opt/kiran/kiran-marketplace/plugins/kiran-noor` (or set `NOOR_PLUGIN`); cases 07–08 need the Episode 8 lab at `~/ep08-lab` (see `../08-team-policy/`). **Running the suite spends real money: set the cap first.**
   ```bash
   python3 --version; claude --version; which bwrap socat
   python3 evals/run_suite.py --help
   ```
2. **Turn on the eval machine policy** (inside WSL/Linux, as root; it backs up your current managed policy). This is an EXAMPLE policy for a separate test machine. Read it first; never apply it to a working seat.
   ```bash
   sudo bash eval-machine/eval_policy.sh on        # expects an existing managed policy (the Episode 8 seat file) to back up; from Windows: wsl -d <distro> -u root -- bash eval-machine/eval_policy.sh on
   ```
3. **Record your own baseline** (pinned model, nothing changed). `suite.sh` sources `env.sh` (isolated config) and runs from the module folder. The runner refuses to start without an isolated `CLAUDE_CONFIG_DIR` or without the eval policy.
   ```bash
   bash eval-machine/suite.sh run_suite.py --runs 5 --max-suite-usd <cap> --timeout-min <minutes> --out evals/baseline.json
   ```
4. **Change one thing, run the same suite, read the report.** Example from the episode (one stage switched):
   ```bash
   bash eval-machine/suite.sh run_suite.py --runs 5 --max-suite-usd <cap> --timeout-min <minutes> \
     --case-model 01-report-mehr=claude-sonnet-5-5 --case-model 02-report-sufi=claude-sonnet-5-5 \
     --case-model 03-report-noor=claude-sonnet-5-5 --case-model 09-plain-sentence=claude-sonnet-5-5 \
     --out evals/runs/after-change.json
   bash eval-machine/suite.sh diff_report.py evals/baseline.json evals/runs/after-change.json --md evals/runs/report.md
   ```
   For a plugin edit, point `--plugin-dir` at the edited copy instead (see `candidates/README.md`).
5. **A person decides, then restore the policy.** Write keep / investigate / roll back on the decision line, follow `UPGRADE-DAY-RUNBOOK.md` (shadow run, one client, all), then always:
   ```bash
   sudo bash eval-machine/eval_policy.sh off
   ```

To read the recorded report without running anything (any OS): `python evals/diff_report.py results/baseline.json results/after-change.json`.
On Windows, set `PYTHONIOENCODING=utf-8` (PowerShell: `$env:PYTHONIOENCODING="utf-8"`) so the `·` separators print correctly.

## Limits — what it does NOT do

- It knows only the nine cases written here. A pass is evidence, not proof; cases you did not write are not tested.
- The script never decides. It prints evidence and an empty decision line; a person fills it in.
- The runner is Linux-only as written (`/tmp` workspaces, `/etc/claude-code/managed-settings.json`, process groups). On Windows, run it inside WSL. It refuses to run outside the eval-machine policy and an isolated config.
- `run_suite.py` does not install or set up the earlier episodes' assets; cases 05–08 fail pre-flight or error without them.
- Costs are client-side estimates at list price, not invoices. The recorded figures came from a subscription login.
- The recorded results came from one machine on one Claude Code release with the models available on record day. Re-test after every Claude Code or model update; models get retired, a pin only buys time.
- Recorded result to know about: the baseline was 7/9, not all green. Case 09 failed 0/5 before any change, and case 05 (must pass) wobbled (4/5 on the baseline, 5/5 in an earlier five-run). A case that wobbles before a change cannot be credited to or blamed on it.
- The chosen change (report stage on a higher tier) made case 09 pass but did not fix its cause (the client name vs the slug), and it raised the report stage cost sharply. A cheaper fix was not tested.
- In `judge-test`, "PASS" means "the report was called ready". With the planted mistake the right result is 0/5, which prints as BELOW MARK.
- `claude plugin eval` shows whether a skill fired; it does not show whether the client's report is right (see `PLUGIN-EVAL-NOTE.md`). On the recorded eval machine it refused shell grants.
- The canary's PowerShell twin is not testable on Linux. Rollback was not rerun (no rollback was decided), and a collaborator downgrade was not tested.
- Editing any file under `evals/cases/` or `evals/expected/` changes the fixture hash; the kit copies had docstrings scrubbed, so your fixture hash will differ from the recorded one. Record your own baseline before comparing.
- `eval-machine/managed-settings.eval.json` is an example only. This pack never applies it for you.
